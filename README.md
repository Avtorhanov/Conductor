# Дирижёр

Программа-«дирижёр» для диагностики и восстановления прошивок микросхем.
Сама определяет, что подключено, выбирает подходящий инструмент, делает резервную копию,
проверяет прошивку и чинит её по проверенному рецепту — только с вашего подтверждения.

**Версия 0.4 — «Мастерская».** Лезвия: SPI-память (flashrom), I2C EEPROM (Bus Pirate 5), ARM (probe-rs,
OpenOCD), AVR, ESP, T48 и **приборы по Modbus RTU** — с настройкой параметров (диапазон, уставка, единицы).
Новые возможности добавляются **навыками** прямо из интерфейса; код каждого раздела открывается в **капоте**
(`</>`), справка — по `?`; **самопроверка** находит и чинит испорченные копии и сломанные правки.

**Штурман** сам спрашивает, чего вы хотите, и подсказывает следующий шаг — с любого экрана:
- `python3 -m dirizher web` — браузер на телефоне, ПК или сенсорном экране прибора (адрес и код доступа он напечатает);
- `python3 -m dirizher` — тот же мастер в терминале (SSH, консоль через USB-UART, маленький экран).

```
подготовка → опознание → напряжение → копия «до» → диагностика → план → запись + сверка + копия «после» → отзыв
```

**Документы:**
- [docs/START.md](docs/START.md) — план старта с нуля до первого ремонта (закупка, установка, первая неделя по дням);
- [docs/MANUAL.md](docs/MANUAL.md) — руководство: сценарии ремонта, неполадки, как развивать систему;
- [docs/SESSION_PROMPT.md](docs/SESSION_PROMPT.md) — промт для сессий разработки с ИИ;
- [docs/STATUS.md](docs/STATUS.md) — текущее состояние и следующие шаги;
- [CHANGELOG.md](CHANGELOG.md) — журнал изменений.

Главные правила — в [PRINCIPLES.md](PRINCIPLES.md). Коротко:
- ничего не пишется без подтверждённой копии «до» и вашего «ДА»;
- после записи всегда идёт сверка и копия «после», откат доступен всегда;
- система всё помнит и учится на результатах ремонтов;
- уникальные данные платы (MAC, серийник) не затираются.

## 1. Что понадобится

**Компьютер-«мозг»:** Raspberry Pi 4/5 с экраном или любой ПК/ноутбук с Linux.

**Железо для первого лезвия:**
- программатор CH341A и прищепка SOIC-8;
- переходник на 1.8 В — для 1.8-вольтовых чипов;
- мультиметр.

**Программы:** Python 3.9+, PyYAML, flashrom; по желанию binwalk.

> ⚠ У популярной «чёрной» платы CH341A на линиях данных бывает 5 В даже в режиме 3.3 В.
> Перед первым подключением проверьте мультиметром напряжение на выводах прищепки.
> Если там 5 В, доработайте плату или купите исправленную версию.

## 2. Установка (Raspberry Pi OS / Debian / Ubuntu)

```bash
sudo apt update
sudo apt install -y python3 python3-yaml flashrom unzip
sudo apt install -y binwalk          # необязательно: разбор структуры дампов

cd ~
unzip dirizher.zip                   # появится папка ~/dirizher
cd ~/dirizher

python3 -m dirizher --version
python3 -m unittest                  # 12 автотестов на симуляторе — должно быть OK
```

Доступ к CH341A без `sudo`:
```bash
sudo cp system/99-dirizher.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger
sudo usermod -aG plugdev $USER       # затем выйдите из системы и войдите снова
```

Все команды выполняются из папки `~/dirizher`.

| Добавить инструмент, протокол, карту параметров или проверку | «Навыки» → «+» в браузере (или папка `skills/<имя>/`, образец — `skills/modbus_rtu/`) |
| Поправить код или профиль с телефона | кнопка `</>` (капот); открыть капот — на экране прибора или `hood.edit: true` |
| Изменить диапазон, уставку прибора | «Штурман» → «Настроить прибор», справка «Пример: сменить диапазон термодатчика» |
| Хранить память и копии на флешке | `config.yaml` → `data_dir: /media/pi/DIRIZHER/data` |
| Держать вторую копию бэкапов | `config.yaml` → `mirror_dir: /путь/ко/второму/диску` |
| Забрать дамп файлом | `python3 -m dirizher export N --to ~/dump.bin` |

> Папку `data/` не выкладывайте в общий доступ: там чужие прошивки, MAC-адреса и серийные номера.

## 4. Первый запуск без железа (симулятор)

Учебный режим `--sim` работает с виртуальной микросхемой и **никогда не трогает настоящее железо**.
У него отдельная память (`data/simulator/`).

```bash
python3 -m dirizher sim reset            # исправная «прошивка»
python3 -m dirizher --sim run            # всё в порядке → «сохранить эталон?» → да

python3 -m dirizher sim corrupt          # «оборвалось обновление»
python3 -m dirizher --sim run            # найдёт повреждение → введите ДА → «заработало?» → да

python3 -m dirizher --sim history        # что система запомнила
python3 -m dirizher --sim rollback 2     # вернуть как было (откат тоже обратим)

python3 -m dirizher sim flaky            # «плохой контакт прищепки»
python3 -m dirizher --sim run            # увидите: запись заблокирована
python3 -m dirizher sim steady

python3 -m dirizher sim erase            # чип стёрт целиком
python3 -m dirizher --sim run            # восстановление + предупреждение про MAC
```

## 5. Первый запуск с настоящей микросхемой

1. **Найдите чип** на плате (8 ножек, маркировка вида `25Q64`, `MX25L6406`). По маркировке найдите даташит и узнайте **напряжение**.
   Для 1.8 В поставьте переходник и укажите `programmer_voltage: 1.8` в `config.yaml`.
2. **Обесточьте устройство**: отключите от сети, разрядите конденсаторы.
3. **Наденьте прищепку**: красный провод — на вывод 1 (точка на корпусе).
4. Проверьте, что инструмент виден:
   ```bash
   python3 -m dirizher plugins             # flashrom_spi должен быть отмечен ✔
   ```
5. **Опознание** (только чтение):
   ```bash
   python3 -m dirizher detect
   ```
   Если точного профиля нет, появится черновик в `data/drafts/`. Заполните его и перенесите в `profiles/chips/`.
6. **Первый раз — пробный режим**. Будет сделана копия и показан план, без записи:
   ```bash
   python3 -m dirizher run --dry-run
   ```
7. **Рабочий запуск**:
   ```bash
   python3 -m dirizher run --label "TV-модель-плата"
   ```
   Если устройство исправно, сохраните дамп как эталон: потом с ним будут сравниваться такие же платы.
8. **Сохраните копию отдельно**, на всякий случай:
   ```bash
   python3 -m dirizher export 1 --to ~/dumps/tv-model-original.bin
   ```

**Если чип не опознаётся на плате.** Через прищепку программатор питает не только чип, но и часть платы.
Попробуйте удерживать процессор платы в сбросе или выпаять чип.

**Не прерывайте запись** и не отключайте питание, пока идёт `запись…`.

## 6. Команды

| Команда | Что делает |
|---|---|
| *(без команды)* или `wizard` | пошаговый мастер-Штурман в терминале |
| `web [--host H] [--port P]` | интерфейс в браузере: ПК, телефон, экран прибора |
| `plugins` | какие инструменты доступны |
| `profiles` | какие профили загружены |
| `detect` | только опознать (ничего не читает целиком) |
| `run [--dry-run] [--image F] [--label L]` | полный цикл |
| `history [-n 20]` | история сеансов |
| `show N` | подробности сеанса N: снимки, журнал |
| `feedback N --ok` / `--fail` | отзыв после проверки устройства вживую (обучение) |
| `reference N [--kind before\|after] [--label L]` | сделать снимок сеанса эталоном |
| `rollback N [--dry-run]` | вернуть на чип копию «до» из сеанса N |
| `export N --kind before --to F` | выгрузить снимок в файл |
| `sim status\|reset\|corrupt\|erase\|flaky\|steady` | учебные поломки симулятора |
| `params` | прочитать параметры прибора по карте профиля (только чтение) |
| `tune --set id=значение [--dry-run]` | изменить параметры: копия «до», план, запись после «ДА», сверка |
| `skills` | навыки: что загружено, что сломано |
| `doctor [--heal]` | самопроверка: копии, память, профили, навыки; `--heal` — починить исправимое |
| `help [слово или имя]` | справка: список, поиск, статья целиком |

Перед командой можно добавить `--sim` (учебный режим) или `--config путь` (другой файл настроек).

## 7. Как система помнит и учится

- **Память** (`data/memory.sqlite` и `data/logs/`): каждый сеанс, отпечаток устройства, команды
  flashrom с выводом, все проверки, что и откуда записано, итог.
- **Копии** (`data/backups/`): все дампы до/после/записанные. Имя файла — SHA-256 содержимого,
  поэтому подмена или порча сразу видна.
- **Эталоны**: дамп исправного устройства. По нему находятся повреждения и восстанавливаются такие же платы.
- **Статистика рецептов**: после ремонта вы отвечаете «заработало?». Чаще помогавшие способы
  поднимаются выше в списке.
- **Черновики профилей**: незнакомый чип не теряется. Система готовит заготовку профиля, вы проверяете её и принимаете.
- **Профили плат**: плата узнаётся по сигнатуре в дампе. Её уникальные области (MAC, серийник,
  калибровки) при ремонте берутся с текущего чипа.
- **«Что помогло»**: после неудачи вы записываете одной фразой, что сделали. В следующий раз при такой же
  неудаче Дирижёр подскажет это первым; подтверждённые подсказки поднимаются выше.
- **Самоисцеление**: самопроверка сверяет каждую копию по SHA-256 и восстанавливает испорченную из второго
  места (`mirror_dir`), а сломанную правку из капота — из истории версий. Только по вашей кнопке.

## 8. Дорожная карта

| Этап | Что | Как |
|---|---|---|
| ✅ 1 | Ядро + SPI-память + симулятор | готово (эта версия) |
| 2 | I2C EEPROM (24Cxx) | плагин через Bus Pirate 5 или i2c-tools, профили 24Cxx |
| 3 | Микроконтроллеры | плагин probe-rs (SWD/JTAG); esptool, avrdude для загрузчиков |
| ✅ 4 | Свой экран | браузер, мастер и Штурман — код готов в 0.2.0, проверить на Pi с сенсорным экраном |
| 5 | Шины и платы | sigrok/PulseView; база V-I сигнатур эталонных плат |
| 6 | Устройства целиком | профили ТВ, роутеров и приборов поверх профилей плат |
| ✅ 7 | Мастерская | навыки, капот, справка, настройка параметров, Modbus RTU, самопроверка — код готов в 0.4.0 |

Каждый этап — это новый файл в `plugins/` и новые профили в `profiles/`. Ядро не переписывается.

## 9. Важно

- Плагин flashrom написан по документированному формату вывода, но **на настоящем железе
  в этой сборке не проверялся**. При первом `detect` загляните в журнал сеанса (`data/logs/`).
  Если JEDEC ID не распознался, поправьте регулярные выражения в `plugins/flashrom_spi.py`
  по реальному выводу `flashrom -p ch341a_spi -V`.
- JEDEC ID в профилях сверяйте с даташитом своей ревизии чипа.
- Работайте только со своими устройствами или с теми, на ремонт которых есть разрешение.
  Используйте только свои дампы и официальные прошивки.
