# Старт проекта: с нуля до первого ремонта

Этот документ — пошаговый план запуска «Дирижёра».
Как пользоваться программой — в [MANUAL.md](MANUAL.md); как продолжать разработку с ИИ — в [SESSION_PROMPT.md](SESSION_PROMPT.md).

---

## 0. Цель первого этапа

Этап 1 считается завершённым, когда выполнено всё:

- [ ] прибор собран, программа установлена, `python3 -m unittest` проходит;
- [ ] пройден учебный сценарий на симуляторе (docs/INSTALL.md, раздел 4);
- [ ] с трёх донорских плат сняты дампы (только чтение), сохранены эталоны;
- [ ] есть минимум 3 своих профиля чипов и 1 профиль платы;
- [ ] выполнено хотя бы одно тренировочное восстановление на доноре, включая откат;
- [ ] проект лежит в git, папка `data/` регулярно копируется во второе место.

Пока этап 1 не закрыт, к новым лезвиям не переходим: всё остальное строится на этом фундаменте.

---

## 1. Закупка

**Этап 1 — обязательно:**
- Raspberry Pi 4 или 5 (от 4 ГБ), родной блок питания, microSD от 32 ГБ (лучше SSD по USB);
- экран (сенсорный 7" или любой HDMI), клавиатура;
- программатор CH341A, прищепка SOIC-8, переходник на 1.8 В;
- мультиметр;
- антистатический браслет или коврик;
- 2–3 донорские платы для тренировки: старый роутер, ТВ-приставка, материнская плата;
- флешка или второй диск — для зеркала резервных копий.

**Этапы 2–3 — позже:**
- Bus Pirate 5 или 6 (I2C/UART/SPI, свой экран, уровни 1.2–5 В);
- 2× Raspberry Pi Pico: один как SWD-отладчик (прошивка debugprobe), второй как логический анализатор;
- лабораторный блок питания с ограничением тока;
- паяльная станция или термовоздух — выпаивать чипы, когда на плате не читается;
- позже универсальный программатор T48 (для minipro).

> Перед первым подключением CH341A проверьте мультиметром напряжение на выводах прищепки.
> У части «чёрных» плат на линиях данных 5 В даже в режиме 3.3 В.

## 2. Рабочее место и безопасность

- Работайте только с обесточенными платами: вилка из розетки, сетевой фильтр выключен.
- Блоки питания и ТВ держат опасное напряжение на конденсаторах и после отключения. Разряжайте их или не трогайте первичную часть.
- Используйте антистатический браслет, хороший свет и лупу. Вывод 1 чипа отмечен точкой или скосом.
- Короткие провода от программатора до прищепки: длинные дают нестабильное чтение.

## 3. Установка на Raspberry Pi

1. Запишите **Raspberry Pi OS (64-bit)** на карту через Raspberry Pi Imager. В настройках Imager задайте имя пользователя, Wi-Fi и включите SSH.
2. Загрузите Pi, затем:
   ```bash
   sudo apt update && sudo apt full-upgrade -y
   sudo apt install -y python3 python3-yaml flashrom binwalk unzip git
   ```
3. Перенесите `dirizher.zip` на Pi (флешкой или `scp dirizher.zip pi@<адрес>:~`) и распакуйте:
   ```bash
   cd ~ && unzip dirizher.zip && cd ~/dirizher
   python3 -m unittest            # должно быть OK
   python3 -m dirizher plugins    # flashrom_spi — ✔
   ```
4. Доступ к CH341A без sudo — docs/INSTALL.md, раздел 2.

## 4. Где хранить данные

`data/` — самое ценное: дампы, эталоны и вся память системы.

- **Просто:** `data_dir` оставить на SD/SSD, `mirror_dir` указать на флешку. Каждая копия дампа будет сразу записываться и туда.
- **Переносимо:** `data_dir` указать на флешку. Тогда знания переезжают вместе с ней на другой прибор.
- **Раз в неделю** копируйте папку `data/` целиком, не во время работы программы:
  ```bash
  rsync -a ~/dirizher/data/ /media/$USER/BACKUP/dirizher-data/
  ```

## 5. Git с первого дня

```bash
cd ~/dirizher
git init
git add .
git commit -m "Дирижёр 0.1.0: ядро, SPI-память, симулятор"
git tag v0.1.0
```

- Удалённый репозиторий делайте **приватным** (GitHub или GitLab).
- Папка `data/` уже исключена в `.gitignore`: дампы, MAC-адреса и серийные номера в git не попадают.
- Каждое новое лезвие ведите в отдельной ветке (`git switch -c stage2-probe-rs`), а в основную ветку вливайте, только когда проходят тесты.
- Каждое изменение записывайте в `CHANGELOG.md`, текущее состояние — в `docs/STATUS.md`.

## 6. Первая неделя по дням

**День 1 — установка и симулятор.**
Установка (docs/INSTALL.md, раздел 2), тесты, учебный сценарий из docs/INSTALL.md (раздел 4). Посмотрите `history`, `show 2` и журнал в `data/simulator/logs/`.

**День 2 — донор №1, только чтение.**
```bash
python3 -m dirizher detect
python3 -m dirizher run --dry-run
python3 -m dirizher run --label "router-XXXX"     # исправен → сохранить эталон: да
python3 -m dirizher export 1 --to ~/dumps/router-XXXX.bin
```
Если `detect` не узнал JEDEC ID, приложите журнал сеанса к сессии с ИИ (SESSION_PROMPT.md, цель «разбор вывода flashrom»).

**День 3 — свои профили.**
1. Черновик из `data/drafts/` сверьте с даташитом (напряжение!) и перенесите в `profiles/chips/`.
2. Сделайте профиль платы по шаблону `profiles/boards/_template_board.yaml`:
   - сигнатура: начало дампа, `hexdump -C ~/dumps/router-XXXX.bin | head`;
   - MAC-адрес с наклейки устройства найдите в дампе:
     ```bash
     cd ~/dumps
     python3 -c "d=open('router-XXXX.bin','rb').read(); print(hex(d.find(bytes.fromhex('001122334455'))))"
     grep -boa "00:11:22:33:44:55" router-XXXX.bin
     ```
     (подставьте свой MAC; первая команда ищет его в двоичном виде, вторая — текстом;
     `-0x1` значит «не найдено»)
   - найденную область впишите в `preserve`.
3. Проверьте: `python3 -m dirizher profiles`, затем снова `run`. Плата должна узнаться по содержимому.

**День 4 — тренировочное восстановление на доноре.**
1. Сделайте копию дампа с одним изменённым байтом в пустой (стёртой) области:
   ```bash
   cd ~/dumps
   python3 -c "d=bytearray(open('router-XXXX.bin','rb').read()); i=d.find(b'\xff'*65536, len(d)//4); assert i>=0, 'нет пустой области'; d[i+100]=0; open('router-test.bin','wb').write(d); print('изменён байт', hex(i+100))"
   ```
   Команда ищет стёртую область 64 КБ подальше от начала и конца чипа: в конце у роутеров часто лежит калибровка радио.
   Если она ответит «нет пустой области», пропустите эту тренировку на этом доноре.
2. `python3 -m dirizher run --image ~/dumps/router-test.bin` → ДА. Это настоящая запись.
3. Проверьте, что донор работает, затем `python3 -m dirizher rollback N` — вернуть оригинал.
4. Ещё раз `run`: дамп должен совпасть с эталоном.

**День 5 — донор №2 на другом чипе, порядок.**
Второй профиль, зеркало копий, `git commit` профилей, запись в `docs/STATUS.md`.
