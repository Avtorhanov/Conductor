# Состояние проекта

Этот файл обновляется в конце каждой сессии разработки и прикладывается к началу следующей.

**Версия:** 0.2.0
**Этап:** 1 — ядро и SPI-память (код готов; идёт проверка на железе) + интерфейсы (код готов, проверен в браузере на симуляторе)

## Готово
- Ядро: сценарий из 7 шагов, память (SQLite + журналы), хранилище копий по SHA-256 с зеркалом,
  правила безопасности, обучение (черновики профилей, рейтинг рецептов, эталоны), откат, выгрузка снимков.
- Плагин `flashrom_spi` (SPI NOR через flashrom).
- Плагин `simulator` (виртуальная W25Q64 с поломками: corrupt, erase, flaky).
- Профили: `generic_spi_nor`, `winbond_w25q64`, `winbond_w25q64fw` (1.8 В), `macronix_mx25l6406`,
  плата `example_sim_board`; шаблоны чипа и платы.
- **Интерфейсы (0.2.0), ядро не менялось:**
  - Штурман (`interface/guide.yaml`, `guide.py`): дерево целей «что будем делать?», подсказки «сейчас важно»
    по журналу (ждёт отзыва, нужен откат, черновик профиля, нет инструментов, нет эталона, нет зеркала),
    «что дальше?» после каждого итога, 19 уроков с примерами (работа и развитие), план из STATUS.md.
  - Браузер (`web.py`, `static/index.html`): телефон, ПК, экран прибора 800×480 и 480×320; без интернета и
    сторонних библиотек; вход по коду (экран прибора — без кода), блокировка после 5 неверных кодов;
    одно задание за раз; «ДА» вводится вручную и проверяется сервером; загрузка образа, скачивание дампов,
    светлая/тёмная тема, размер текста.
  - Текстовый мастер (`wizard.py`): SSH, консоль USB-UART, маленькие экраны; `python3 -m dirizher` без команды.
  - Конструктор профиля чипа (`builder.py`): форма → проверка → YAML → черновик → включение только после
    подтверждения человека; ничего не перезаписывает.
  - `system/dirizher-web.service`, `system/kiosk.sh`.
- 42 автотеста на симуляторе (12 ядра + 30 интерфейсов: Штурман, конструктор, HTTP-цикл, вход, мастер).
- Документация: README, PRINCIPLES, START, MANUAL (+ разделы 1.0, 1.5, 2.7, 2.8), SESSION_PROMPT, CLAUDE.md.

## Проверить на железе
- [ ] Разбор вывода flashrom: строка `Found … flash chip "…" (N kB, SPI)`, JEDEC ID из строки
      `probe_spi_rdid…: id1 0x…, id2 0x…`, случай «несколько определений». Проверено только на подставной программе.
- [ ] Время чтения и записи 8 МБ через CH341A (таймауты 900 / 1800 с).
- [ ] JEDEC ID `EF6017` для W25Q64FW — сверить с даташитом.
- [ ] Поведение при чтении чипа на плате (без выпаивания).
- [ ] Служба `dirizher-web` на Pi: пользователь, группа plugdev, остановка во время записи (SIGINT, ожидание).
- [ ] Киоск: имя браузера (`chromium-browser` / `chromium`) и автозапуск (labwc или LXDE) на вашей версии ОС.
- [ ] Телефон по Wi-Fi: адрес из консоли, вход по коду; точка доступа `nmcli … hotspot`.
- [ ] Сенсорный экран: размер кнопок пальцем, отсутствие цветных эмодзи (значки скрываются сами).

## Принятые решения
- Движки (flashrom, probe-rs и др.) не встраиваются, а вызываются отдельными процессами: лицензии GPL, разные языки, независимые обновления.
- У симулятора отдельная память (`data/simulator/`), чтобы учебные эталоны не смешивались с настоящими.
- Эталоны ищутся по ключу чипа (класс + JEDEC ID). Эталон с другого профиля — только после подтверждения человеком.
- При восстановлении области `preserve` берутся с текущего чипа. Если они пусты — предупреждение.
- Интерфейсы — отдельный слой `interface/`; ядро не менялось. Все экраны берут вопросы и подсказки из одного Штурмана.
- Веб — только стандартная библиотека Python (без Flask и CDN): работает офлайн, ставить нечего.
- «Отмена» на экране = безопасный ответ ядру (как пустой ввод в консоли); на паузе перед началом — прерывание сеанса.
- Слово подтверждения вводится вручную и проверяется на сервере; кнопкой не заменяется.
- Профиль из конструктора включается только после галочки «сверил с даташитом» и с указанным напряжением; файлы не перезаписываются.
