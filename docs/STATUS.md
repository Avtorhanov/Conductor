# Состояние проекта

Этот файл обновляется в конце каждой сессии разработки и прикладывается к началу следующей.

**Версия:** 0.6.0
**Этап:** 1 — ядро и SPI-память (код готов; идёт проверка на железе) + интерфейсы (код готов, проверен в браузере на симуляторе) + лезвия этапов 2–3 (код готов, проверен на подставных программах, ждёт железа) + **мастерская** (код готов, проверен на симуляторе, эмуляторе Modbus и в браузере) + **справочник и демо на GitHub Pages** (опубликовано: https://avtorhanov.github.io/Conductor/) + **приложение на телефоне — PWA** (код готов, установка проверена в Chrome на ПК; на телефоне не проверено) + **вёрстка под телефон 0.5.2** (по замечаниям с iPhone; проверена в Chrome, на iPhone не проверена) + **учебная площадка 0.6.0** (тренажёр по маршрутам; проверен в Chrome и тестами, на телефоне и экране Pi не проверен)

## Готово
- Ядро: сценарий из 7 шагов, память (SQLite + журналы), хранилище копий по SHA-256 с зеркалом,
  правила безопасности, обучение (черновики профилей, рейтинг рецептов, эталоны), откат, выгрузка снимков.
- Ядро 0.3.0: своё напряжение адаптера у каждого плагина (`programmer_voltage` в настройках плагина);
  проверка `binwalk_expect` (ожидаемые сигнатуры в дампе).
- **Ядро 0.4.0 (только добавления, прежние сценарии не менялись):**
  - карта параметров `core/params.py` (поле профиля `params`, окно шины `bus`): u8…i32, f32, BE/LE, scale,
    min/max, choices, только чтение; `register:` для Modbus;
  - сценарии `Conductor.read_params()` (только чтение) и `Conductor.tune(changes)` — копия «до» → план
    «было → стало» → `write_blockers` → слово «ДА» → `apply()` (сверка, копия «после») → при неудаче возврат «до»;
  - навыки `core/skills.py`: `skills/<id>/` (паспорт, код, профили, справка), сторож кода (lint), загрузка
    без перезапуска; реестр берёт лезвия из навыков и перечитывает изменённые файлы плагинов;
  - `Plugin.voltage_check = False` — для приборов с развязанной шиной (RS-485) вместо вопроса о напряжении;
  - «что помогло» (`learning.signature/remember_fix/confirm_fix/hints`, таблица `fixes`);
  - самоисцеление копий: `BackupStore.health/repair` (испорченный файл — в `data/quarantine/`).
- Плагин `flashrom_spi` (SPI NOR через flashrom).
- Плагин `simulator` (виртуальная W25Q64 с поломками: corrupt, erase, flaky); у учебной платы — 3 параметра.
- **Лезвия (0.3.0), все выключены по умолчанию, см. docs/INTEGRATIONS.md:**
  `probe_rs` и `openocd` (ARM по SWD/JTAG), `avrdude` (AVR, образ flash+EEPROM),

  помощник-процесс `skills/modbus_rtu/rtu.py` (stdlib, функции 3/4/6/16, CRC, повторы, эхо);
  запись только изменившихся регистров; профили `thermo_example` (учебная карта термопреобразователя,

- **Вёрстка под телефон (0.5.2), только `static/index.html`, по скриншотам с iPhone:**
  - шапка без просвета: всё, что выше края экрана, залито цветом шапки (`.top::before`, `position: fixed`,
    `bottom: 100%`) — на iOS 26 страница рисуется и под строкой состояния; полосу демо заливка не закрывает.
    То же под нижним меню (`.tabs::after`). `theme-color` страницы и `theme_color` манифеста = цвет шапки `#08112a`;
  - нижнее меню: колонки `repeat(6, minmax(0, 1fr))` — длинное слово больше не раздвигает сетку и не выталкивает
    «Прибор» за край; вкладки — скруглённые прямоугольники (радиус 14 px вместо 999 px); подписи не вылезают

  - копирование команд: значок (два листа → галочка на 1,5 с) рядом с полем, а не кнопка «Копировать» поверх
    текста; длинные команды переносятся (`pre-wrap`) — команда видна целиком.
  Проверено в Chrome: 390×844 и 360×740 (тёмная и светлая), 480×320, 800×480, 1280×800 — горизонтальной
  прокрутки нет, подписи целиком, значок справа от поля, копирование кладёт в буфер исходную команду.

- [ ] Сенсорный экран: размер кнопок пальцем, отсутствие цветных эмодзи (значки скрываются сами);

## Принятые решения
- Движки (flashrom, probe-rs и др.) не встраиваются, а вызываются отдельными процессами: лицензии GPL, разные языки, независимые обновления.
- У симулятора отдельная память (`data/simulator/`), чтобы учебные эталоны не смешивались с настоящими.
- Эталоны ищутся по ключу чипа (класс + JEDEC ID). Эталон с другого профиля — только после подтверждения человеком.
- При восстановлении области `preserve` берутся с текущего чипа. Если они пусты — предупреждение.
- Интерфейсы — отдельный слой `interface/`. Все экраны берут вопросы и подсказки из одного Штурмана.
- Веб — только стандартная библиотека Python (без Flask и CDN): работает офлайн, ставить нечего.
- «Отмена» на экране = безопасный ответ ядру (как пустой ввод в консоли); на паузе перед началом — прерывание сеанса.
- Слово подтверждения вводится вручную и проверяется на сервере; кнопкой не заменяется.
- Профиль из конструктора включается только после галочки «сверил с даташитом» и с указанным напряжением; файлы не перезаписываются.
- (0.3.0) Напряжение адаптера задаётся у каждого плагина: USBasp 5 В, CH341A 3.3 В, BP5 регулируемый.
- (0.3.0) Bus Pirate 5 управляется через помощника-процесс на stdlib (termios), а не через pyserial в ядре.
- (0.3.0) AVR: образ = flash + EEPROM. Фьюзы и lock-биты не читаются в образ и никогда не пишутся.
- (0.3.0) Модель МК для probe-rs/OpenOCD и модель 24Cxx задаёт человек; уверенность 0.7–0.75.
- (0.3.0) Опасные параметры отклоняются до запуска программы, даже если вписаны в extra_args.
- (0.3.0) minipro не обслуживает микроконтроллеры — для AVR есть avrdude.
- (0.3.0) sigrok-cli — не лезвие, а отдельный модуль `dirizher.extras.sigrok`.
- (0.3.2) Тема «Нави» заменила тёмную (не третья тема): меньше вариантов для проверки. Сохранённое «dark»
  открывается как «Нави». Форма и объём заданы переменными CSS; светлая тема их обнуляет и выглядит как раньше.
- (0.3.2) Шрифты не загружаются из сети и не раздаются `web.py`: заголовки берут Exo 2, только если он установлен.
- (0.4.0) Универсальность — через **карту параметров**, а не через код под каждый прибор: параметр = типизированное
  поле в образе памяти. Одинаково для EEPROM, блока конфигурации во флеше и регистров Modbus. Запись параметров —
  тот же путь, что и любая запись (копия «до», сверка, «ДА», копия «после»).
- (0.4.0) Изменение ядра: добавлены `tune/read_params`, загрузка навыков, `voltage_check`, таблица `fixes`,
  `health/repair` хранилища. Без этого параметры, навыки и самоисцеление не встраиваются в общую защиту;
  прежние сценарии и тесты не тронуты.
- (0.4.0) Капот правит только то, что расширяет Дирижёр. Ядро, `config.yaml`, сторож лезвий, симулятор и
  интерфейсы — только просмотр: в них защита и эталоны тестов, их меняют через git с тестами.
- (0.4.0) Капот закрыт по умолчанию: правка кода = выполнение кода на приборе. Открыть — физически с экрана
  прибора (до перезапуска) или `hood.edit: true`; с телефона открыть нельзя. Код и профили — со словом «ДА».
- (0.4.0) Сторож кода — не песочница: ловит ошибки (удаление файлов, процессы мимо `self.run()`, eval/exec,
  запись из `probe()`, доступ к хранилищу копий), а не злой умысел. Пробный импорт — отдельным процессом.
- (0.4.0) Самоисцеление чинит только доказуемое: копию — из места, где SHA-256 сходится; правку — версией
  из истории, которая проходит проверку. Только по кнопке человека или `doctor --heal`. Ничего не удаляется:
  испорченное — в карантин, прежние версии — в историю.
- (0.4.0) Самообучение — «что помогло» словами человека, с счётчиком подтверждений; без догадок и автодействий.
- (0.4.0) Modbus RTU — помощник-процесс на stdlib (как BP5); прибор = окно регистров настроек; модель задаёт
  человек; адрес и скорость в учебной карте — только чтение (после их смены сверка по старому адресу невозможна).
- (0.4.0) Окно чтения Modbus — только регистры настроек: живые величины ломают сверку повторных чтений,
  и запись блокируется (проверено тестом).

- (0.5.0) Справочник — не код, а данные: карточки YAML в `catalog/`, рисунки описаны данными и рисуются
  интерфейсом (SVG без картинок и сети). Новый переходник или движок — новая карточка, ядро не меняется.
- (0.5.0) Карточки только описывают — правятся в капоте без слова «ДА», но с той же проверкой, что при загрузке.
- (0.5.0) Авторы движков обязательны (самопроверка напоминает): справочник отдаёт должное открытым проектам,
  на которых стоит Дирижёр. Сведения об авторах — из man-страниц, сайтов и репозиториев проектов.
- (0.5.0) Демо на GitHub Pages — та же страница плюс подмена связи; ходы записывает настоящее ядро на симуляторе,
  а не отдельная имитация в JS. Поэтому демо не расходится с прибором: меняется ядро или Штурман — меняется демо.
- (0.5.0) Ядро не менялось. Изменены только слой интерфейсов и мастерская (web, index.html, guide, wizard,
  hood, doctor, helpdocs, skillmaker, `__main__`).
- (0.5.0) Демо публикуется только из `main` (как в workflow) — вопрос закрыт.
- (0.5.1) Приложение на телефоне — PWA, а не APK: та же страница, нечего собирать и подписывать, нет второго кода.
- (0.5.1) Сервис-воркер — только по HTTPS и никогда для `/api/…`: экран прибора не должен показывать устаревшее
  состояние из кэша. Файлы приложения отдаются без кода входа — в них нет данных прибора.
- (0.5.2) Вкладки «Нави» — скруглённые прямоугольники (14 px), а не «таблетки»: на шести узких кнопках телефона
  полукруг съедал место под подпись. Решение отменяет «полукруглые вкладки» из 0.3.2; объём (тени) прежний.
- (0.5.2) Короткая подпись только на телефоне: «Справочник» → «Каталог» (≤480 px в портрете). Раздел, справка,
  капот и ПК по-прежнему называют его «Справочник»; экранный диктор читает полное имя (`aria-label`).
- (0.5.2) Просвет над шапкой закрывается заливкой «над краем экрана» (`position: fixed`), а не полупрозрачным
  размытием и не переносом полосы демо: работает без JS, полоса демо остаётся видна. Ядро не менялось.
- (0.6.0) Учебная площадка — данные (`playground.yaml`), как Штурман и справочник: маршрут или шаг добавляется без
  кода, правится в капоте без слова «ДА» (учебный текст, на железо не влияет). Одна страница на прибор, демо и
  отдельный файл; текстовый режим — тот же файл.
- (0.6.0) Тренажёр ничего не выполняет: в нём нет кнопок, которые запускают задания ядра. Что нажать в Дирижёре —
  написано словами («В Дирижёре»), а переход — обычной ссылкой «← Дирижёр».
- (0.6.0) «Сеансы вживую» — не отдельная имитация, а сокращённые протоколы настоящего ядра; тест сверяет каждую
  строку с выводом ядра на учебной микросхеме (числа и отпечатки не сравниваются). Меняется текст ядра — тест
  подскажет обновить тренажёр. Строки «~» — примеры вывода настоящих программ (flashrom), они не сверяются.
- (0.6.0) Прибор отдаёт страницу и данные площадки без кода входа (`web.PLAYGROUND_FILES`): там только учебный
  текст, ни данных прибора, ни действий — как файлы PWA.
- (0.6.0) Мишени площадки — только свои устройства, без обхода защит: рабочие телефон, iPad и ТВ — экраны и
  тренажёры, машина — только чтение, ЭБУ не прошивается; запись — на учебных чипах и донорах.

## Открытые вопросы
- Нужна ли полная установка приложения с самого прибора? Тогда нужен HTTPS на Pi (свой сертификат и его
  установка на телефон) — отдельная цель; сейчас с прибора — ярлык, полная установка — у демо.
- Форм-фактор: Raspberry Pi 5 + сенсорный 7" или ноутбук? (интерфейс готов к обоим)
- Какие устройства чинить в первую очередь (определяет порядок профилей и включения лезвий)?
- Нужен ли постоянный код доступа по умолчанию или случайный при каждом запуске (сейчас — случайный)?
- Нужен ли второй транспорт для 24Cxx — I2C самого Raspberry Pi (i2c-tools) — помимо Bus Pirate 5?
- Какие приборы с параметрами первыми (модель термопреобразователя/регулятора, протокол, паспорт с картой регистров)?
- Нужен ли Modbus TCP (приборы в локальной сети) — тот же навык с другим транспортом?
- Править капотом с телефона насовсем (`hood.edit: true`) или только с экрана прибора?
- Подпись вкладки на телефоне: «Каталог» устраивает или переименовать раздел целиком (везде одно имя)?
