# Состояние проекта

Этот файл обновляется в конце каждой сессии разработки и прикладывается к началу следующей.

**Версия:** 0.3.1
**Этап:** 1 — ядро и SPI-память (код готов; идёт проверка на железе) + интерфейсы (код готов, проверен в браузере на симуляторе) + лезвия этапов 2–3 (код готов, проверен на подставных программах, ждёт железа)

## Готово
- Ядро: сценарий из 7 шагов, память (SQLite + журналы), хранилище копий по SHA-256 с зеркалом,
  правила безопасности, обучение (черновики профилей, рейтинг рецептов, эталоны), откат, выгрузка снимков.
- Ядро 0.3.0: своё напряжение адаптера у каждого плагина (`programmer_voltage` в настройках плагина);
  проверка `binwalk_expect` (ожидаемые сигнатуры в дампе).
- Плагин `flashrom_spi` (SPI NOR через flashrom).
- Плагин `simulator` (виртуальная W25Q64 с поломками: corrupt, erase, flaky).
- **Лезвия (0.3.0), все выключены по умолчанию, см. docs/INTEGRATIONS.md:**
  `probe_rs` и `openocd` (ARM по SWD/JTAG), `avrdude` (AVR, образ flash+EEPROM),
  `esptool` (ESP8266/ESP32, v4 и v5), `minipro` (T48/TL866II+, класс по имени чипа),
  `bp5_i2c` (Bus Pirate 5, I2C EEPROM 24C01…24C512, помощник-процесс `helpers/bp5_i2c.py`).
  Общие помощники `plugins/_common.py`: запрет опасных параметров (guard), подсказка про защиту чтения,
  разбор текстовых дампов. Замер логическим анализатором: `python3 -m dirizher.extras.sigrok`.
- Профили: `generic_spi_nor`, `winbond_w25q64`, `winbond_w25q64fw` (1.8 В), `macronix_mx25l6406`,
  плата `example_sim_board`; новые — `stm32f103c8`, `atmega328p`, `esp32_4mb`, `eeprom_24c02`
  и общие `generic_mcu_arm`, `generic_avr`, `generic_esp`, `generic_i2c_eeprom`, `generic_parallel`; шаблоны чипа и платы.
- **Интерфейсы (0.2.0), ядро не менялось:**
  - Штурман (`interface/guide.yaml`, `guide.py`): дерево целей «что будем делать?», подсказки «сейчас важно»
    по журналу (ждёт отзыва, нужен откат, черновик профиля, нет инструментов, нет эталона, нет зеркала),
    «что дальше?» после каждого итога, 27 уроков с примерами (работа и развитие), план из STATUS.md.
    С 0.3.1 — раздел «Подключить инструмент» (уроки по каждому новому лезвию) и действие «замер» (sigrok).
  - Браузер (`web.py`, `static/index.html`): телефон, ПК, экран прибора 800×480 и 480×320; без интернета и
    сторонних библиотек; вход по коду (экран прибора — без кода), блокировка после 5 неверных кодов;
    одно задание за раз; «ДА» вводится вручную и проверяется сервером; загрузка образа, скачивание дампов,
    светлая/тёмная тема, размер текста.
  - Текстовый мастер (`wizard.py`): SSH, консоль USB-UART, маленькие экраны; `python3 -m dirizher` без команды.
  - Конструктор профиля чипа (`builder.py`): форма → проверка → YAML → черновик → включение только после
    подтверждения человека; ничего не перезаписывает.
  - `system/dirizher-web.service`, `system/kiosk.sh`.
- udev: `99-dirizher.rules` (CH341A), `99-dirizher-tools.rules` (USBasp, ST-Link V2/V2-1/V3, T48/TL866II+, fx2lafw).
- Автотесты: 42 на симуляторе (12 ядра + 30 интерфейсов) + 54 лезвий без железа (полный цикл каждого
  лезвия, только чтение при опознании, запреты, защита чтения, версии программ, эмулятор Bus Pirate 5).
  + 7 тестов Штурмана для инструментов. Все 103 проходят вместе.
- Документация: README, PRINCIPLES, START, MANUAL (+ разделы 1.0, 1.5, 2.7, 2.8), INTEGRATIONS, SESSION_PROMPT, CLAUDE.md.

## Проверить на железе
- [ ] Разбор вывода flashrom: строка `Found … flash chip "…" (N kB, SPI)`, JEDEC ID из строки
      `probe_spi_rdid…: id1 0x…, id2 0x…`, случай «несколько определений». Проверено только на подставной программе.
- [ ] Время чтения и записи 8 МБ через CH341A (таймауты 900 / 1800 с).
- [ ] JEDEC ID `EF6017` для W25Q64FW — сверить с даташитом.
- [ ] Поведение при чтении чипа на плате (без выпаивания).
- [ ] Служба `dirizher-web` на Pi: пользователь, группа plugdev, остановка во время записи (SIGINT, ожидание).
- [ ] Киоск: имя браузера (`chromium-browser` / `chromium`) и автозапуск (labwc или LXDE) на вашей версии ОС.
- [ ] Телефон по Wi-Fi: адрес из консоли, вход по коду; точка доступа `nmcli … hotspot`.
- [ ] Сенсорный экран: размер кнопок пальцем, отсутствие цветных эмодзи (значки скрываются сами).
- [ ] Bus Pirate 5: меню `m` (поиск пункта I2C по тексту), вопросы после `W 3.3`, раскраска VT100,
      перенос длинной строки `RX:`, время чтения 24C256.
- [ ] probe-rs: формат вывода `probe-rs read b8` и `probe-rs info`; флаг `--binary-format`/`--format`.
- [ ] OpenOCD: строки DPIDR / «processor detected» / «Target voltage»; нужен ли `reset halt`.
- [ ] minipro: строка `Chip ID: 0x… OK`, текст при несовпадении ID, ответ `-D` для чипов без ID.
- [ ] avrdude: строка подписи (6.x и 7–8.x), срезание хвоста 0xFF при чтении flash.
- [ ] esptool: строки `Chip is` / `Chip type:`, `MAC:`, `Detected flash size` (v4 и v5).
- [ ] binwalk_expect: названия сигнатур на исправных дампах реальных плат.
- [ ] sigrok-cli: драйвер анализатора, синтаксис декодера SPI.
- [ ] VID:PID в `system/99-dirizher-tools.rules` — сверить с `lsusb`.

## Принятые решения
- Движки (flashrom, probe-rs и др.) не встраиваются, а вызываются отдельными процессами: лицензии GPL, разные языки, независимые обновления.
- У симулятора отдельная память (`data/simulator/`), чтобы учебные эталоны не смешивались с настоящими.
- Эталоны ищутся по ключу чипа (класс + JEDEC ID). Эталон с другого профиля — только после подтверждения человеком.
- При восстановлении области `preserve` берутся с текущего чипа. Если они пусты — предупреждение.
- Интерфейсы — отдельный слой `interface/`; ядро не менялось. Все экраны берут вопросы и подсказки из одного Штурмана.
- Веб — только стандартная библиотека Python (без Flask и CDN): работает офлайн, ставить нечего.
- «Отмена» на экране = безопасный ответ ядру (как пустой ввод в консоли); на паузе перед началом — прерывание сеанса.
- Слово подтверждения вводится вручную и проверяется на сервере; кнопкой не заменяется.
- Профиль из конструктора включается только после галочки «сверил с даташитом» и с указанным напряжением; файлы не перезаписываются.
- (0.3.0) Напряжение адаптера задаётся у каждого плагина: USBasp 5 В, CH341A 3.3 В, BP5 регулируемый.
- (0.3.0) Bus Pirate 5 управляется через помощника-процесс на stdlib (termios), а не через pyserial в ядре:
  та же изоляция, что у внешних программ, и никаких новых зависимостей.
- (0.3.0) AVR: образ = flash + EEPROM, потому что запись flash стирает весь чип вместе с EEPROM.
  Фьюзы и lock-биты не читаются в образ и никогда не пишутся.
- (0.3.0) Модель МК для probe-rs/OpenOCD и модель 24Cxx задаёт человек (надёжного ID по шине нет);
  уверенность опознания 0.7–0.75 и честная пометка «модель из настроек».
- (0.3.0) Опасные параметры (снятие защиты, стирание всего чипа, фьюзы, отключение проверок)
  отклоняются до запуска программы, даже если вписаны в extra_args.
- (0.3.0) minipro не обслуживает микроконтроллеры (стирание заденет EEPROM и фьюзы) — для AVR есть avrdude.
- (0.3.0) sigrok-cli — не лезвие (ничего не пишет), а отдельный модуль `dirizher.extras.sigrok`;
  `__main__.py`, `config.yaml` и интерфейсы пакет 0.3.0 не меняет.
