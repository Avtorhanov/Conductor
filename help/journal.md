# Журнал для разработки

Разбор вывода flashrom, probe-rs и других программ написан по документации. Ваш первый прогон на железе
делает его проверенным: из журнала получается постоянный тест.

**Что в журнале.** Команды, коды возврата, полный вывод программ (до 1 МБ на поток), версии программ,
отпечаток чипа и итог сеанса. **Дампов нет** — содержимое чипа туда не попадает никогда.

**Что убрано.** MAC-адреса заменены на `02:00:00:…`, серийные номера и «Serial code» — на `SERIAL-1`,
имя прибора — на `host`, домашние папки — на `~`. Один и тот же MAC везде получает одну и ту же замену.

## Как передать

- **С телефона:** «Журнал» → сеанс → «Скачать журнал для разработки». Прибор работает, телефон
  скачивает файл `dirizher_journal_sN.json` — его можно переслать как обычный файл.
- **В терминале:** `python3 -m dirizher journal N --to журнал.json` (без `--to` — только сводка).

Номер сеанса `N` — в «Журнале» или `python3 -m dirizher history`.

## Что делает разработчик

`python3 tools/log_to_test.py журнал.json` кладёт фикстуру в `tests/fixtures/real/` и сразу проверяет,
что плагин разбирает этот вывод так же. Ожидаемое берётся из сеанса — сверьте его с маркировкой чипа;
если разбор был неверный, поправьте `expect` (или `--expect jedec_id=…`), и тест будет падать, пока
разбор не исправят. Тест — `python3 -m unittest tests.test_real_outputs`.

Где лежит полный вывод на приборе: `data/logs/session_NNNNN/cmd_NNN.json`, рядом с журналом сеанса.
Файлы только добавляются, ничего не переписывается.
